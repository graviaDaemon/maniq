# Maniq

Maniq is a statically typed, ahead-of-time compiled programming language with C/Arduino-style syntax. One codebase is
meant to compile to **Windows, Linux, macOS, iOS and Android**, for both console programs and GUI applications.

The compiler, `maniq`, is written in C++26. It emits C23 and hands that to the platform's C compiler (clang,
gcc, Xcode, the Android NDK), so one backend covers every target.

---
DISCLAIMER:
The lexical syntax (`Writerside/topics/grammar.md`), the `.tokens`, `.ast` and `.err` files have all been crafted by hand.
Most of the CPP and C code has been generated by Claude-Code since my knowledge there is lacking a bit, but I've reviewed each bit of the code
to ensure it's all per my expectations.
The Error Codes are my design, and are being followed throughout.

---

> **Status: pre-alpha.** This is a personal project to learn how compilers work, built one phase at a time. The
> v0 subset (int, bool, functions, if/else, while, print) compiles to a native executable. Next: the test harness.

## A taste

```text
@max(int a, int b) << int {
    if (a > b) {
        return a;
    }
    return b;
}

@main() << void {
    int biggest = max(3, 7);
    print(biggest);
}
```

More examples are in [`samples/`](samples). They show where the syntax is heading, not just what works today.

## Building

You need CMake 3.28 or newer and gcc 14 or newer (C++26 for `maniq`, C23 for the C it generates; GCC 15 is used for
development), both on PATH. On Windows, set the environment variable `CMAKE_GENERATOR` to `MinGW Makefiles` once,
because CMake otherwise picks Visual Studio.

```bash
cmake --workflow --preset dev        # configure, build and run every test
./build/maniq lex samples/hello.mq
./build/maniq parse samples/v0-good.mq
./build/maniq build samples/v0-good.mq
```

`lex` and `parse` print the token list and the syntax tree. `build` lexes, parses, type-checks and generates C23; it
writes `out.tokens`, `out.ast`, `out.types` and `out.c` to the current folder, compiles `out.c` with `gcc -std=c23 -O2`
into `v0-good.exe`, and prints errors and warnings to stderr. gcc 15 must be on PATH.

## Tests

The tests are golden files, each compared with the output for `samples/<name>.mq`:

| Golden file                 | Expected                                                            |
|-----------------------------|---------------------------------------------------------------------|
| `tests/lex/<name>.tokens`   | `maniq lex` output                                                  |
| `tests/parse/<name>.ast`    | `maniq parse` output                                                |
| `tests/err/<name>.err`      | errors and warnings from `maniq build` (empty for a clean build)    |
| `tests/types/<name>.types`  | the typed tree `maniq build` writes to `out.types`                  |
| `tests/c/<name>.c`          | the C `maniq build` writes to `out.c`                               |
| `tests/run/<name>.out`      | what the compiled program prints (stdout and stderr)                |

A sample named `v0-mq<code>.mq` or `v0-mq<code>-<case>.mq` contains exactly one error or warning with that code; the
codes are listed in [Error codes](Writerside/topics/errorcodes.md).

Every `v0-*` sample is tested at all six stages, other samples only by the lexer. A golden file must exist exactly
when its stage applies (a sample that fails to build has no `.c`), so a sample can't go untested.

```bash
cmake --workflow --preset dev        # run everything (in parallel); a failure prints its diff
ctest --test-dir build -L run        # only one stage, by label
cmake --workflow --preset bless      # write the golden files from the current output...
git diff tests/                      # ...and review every change before committing
```

The suite runs on Linux through GitHub Actions on every push. To run it locally before every push as well:
`git config core.hooksPath .githooks` (once per clone; skip a single push with `git push --no-verify`).
